# 代码改动与技能同步

任何代码改动完成后（包括新增功能、修改行为、调整口径、重命名路径/常量、修 Bug、改配置/脚本），必须检查项目技能库是否仍然与实现一致，并在最终回复前完成同步。

**强制同步范围（任何代码改动都适用，缺一不可）**：

1. **更新技能**：同步 `.trae/skills/` 下对应 `SKILL.md`——文件路径、入口函数、常量名与默认值、计算口径、流程步骤、限制条件、验证方法；无可覆盖技能且改动可复用时新建技能。
2. **更新文案**：同步所有受影响的用户可见文案——页面策略规则说明/口径提示、按钮与确认框标题、进度与失败汇总提示、空状态与错误提示、表格列名、Excel 导出列名与汇总行、tooltip 标签等。**数字/阈值/窗口/持有天数类文案必须继续从 `appConfig` 插值，禁止在文案里写死。**
3. **更新使用手册（页面代码改动必做）**：任何页面 / 功能 / 交互 / 展示 / 文案改动完成后，必须同步 `Front-End/src/config/userManualConfig.ts` 中对应 `menuKey` 的 `features`：
   - 新增页面 → 新增一条 `{ menuKey, features }`；
   - 已有页面行为变化（新增/删除 tab、列、按钮、筛选、口径、跳转、交互）→ 修改或补充该条目，删除已失效的描述；
   - `menuKey` 必须与 `menuConfig.tsx` 中叶子菜单的 `key` 完全一致；
   - 只写用户可见功能与操作结果，不写内部实现细节；如涉及接口口径差异，用一句用户能看懂的说明。
4. **更新公共入口**：如改动涉及技能索引、文档索引、常用命令或开发约定，同步根目录 `AGENTS.md`。

漏改技能、使用手册或文案任一项，都视为本次任务未完成，不得直接交付。

**公共入口约定**：根目录 `AGENTS.md` 是所有 AI IDE（Trae / Claude Code / Cursor / Copilot / Gemini / Windsurf / Cline 等）的公共入口，内含开发约定、目录说明、技能索引与文档索引。`.trae/skills/` 是技能详文唯一真相源，`.claude/skills` 是指向它的软链。其它 IDE 的入口文件（`CLAUDE.md`、`GEMINI.md`、`.cursor/rules/*.mdc`、`.cursorrules`、`.github/copilot-instructions.md`、`.windsurf/rules/*`、`.clinerules/*`）只做薄指针，**不要在其中重复维护规则**。

## 执行时机

- 改动已通过自测/类型检查，准备给出最终总结之前。
- **每次改动页面代码（页面 / 组件 / 路由 / 页面配置）都必须检查并同步使用手册**；即使只是调整列、tab、按钮、筛选、文案，也不能跳过。
- 一次任务涉及多个模块时，每个受影响的技能都要处理。
- 纯分析、纯排查、仅解释代码、无实际改动时**不触发**。
- **改动了公共方法 / 策略 / 计算内核**（如 `src/utils/stockUtils.ts`、`src/utils/buyPointCompute.ts`、`src/config/appConfig.ts` 的新字段或口径调整）时，除同步技能外，**必须补充或更新测试用例并跑通**（见步骤 2.5）。

## Git 暂存约定

- 修改完成后**不要**替用户执行 `git add` / `git add .` / `git add -A`，也不要主动暂存任何文件；改动保留在工作区即可。
- 暂存由用户自行完成；仅当用户明确要求暂存或提交时，才按指令执行。

## 步骤

1. **归纳改动范围**
   - 列出受影响的前端页面/路由、组件、工具函数、Worker、后端接口、脚本、配置、常量与数据口径。
   - 记录「行为变化」而不只是「文件变化」：入口、默认值、限制条件、UI 展示、数据结构、异常处理。
   - 同时列出受影响的**用户可见文案**：页面规则说明、口径提示、按钮/确认框、进度与失败提示、空状态、表格列名、导出列名与汇总行、tooltip 标签。
   - 列出受影响的**使用手册条目**：本次改动涉及哪些 `menuKey`，对应的 `features` 需要新增、修改还是删除。

2. **定位对应技能**
   - 技能根目录固定为 `<workspaceFolder>/.trae/skills/<skill-folder>/SKILL.md`（`.claude/skills` 软链到同一目录，无需另存一份）。
   - 用改动涉及的路径、页面路由、函数名、常量名、业务名词在技能库中检索 `description` 与正文。
   - 一个改动可能命中多个技能；不要只看名字，看 `description` 的触发条件与正文中的文件清单。
   - 同时检查根目录 `AGENTS.md` 的「技能索引 / 文档索引」是否仍准确（新增或重命名技能、移动文档时必须同步）。

2.5. **补充测试用例（公共方法改动时必做）**

   当改动涉及**公共方法 / 策略计算内核 / RSI/分位/收益率口径 / Worker 输入输出**（见下方清单）时，必须在 `Front-End/test/` 下补充或更新测试用例，并跑通：

   | 改动类型 | 测试位置 | 命令 |
   |---------|---------|------|
   | 新增/修改 stockUtils.ts 的导出函数 | `Front-End/test/stockUtils-extra.test.ts`（通用纯函数）+ `Front-End/test/asof-rolling.test.ts`（策略/as-of 口径） | `cd Front-End && npm test`（跑 `test/*.test.ts` 全部用例） |
   | 新增/修改 buyPointCompute.ts / Worker 输入输出 | `Front-End/test/buyPointCompute.test.ts`（个股/指数/大宗商品/基金四条路径 + ★5 卖出） | 同上 |
   | 新增/修改买入卖出报告 / 买入计划导出 | `Front-End/test/buySellReportExport.test.ts`（列构建、★5 配对筛选） | 同上 |
   | 新增/修改 appConfig.rsi / appConfig.batch / appConfig.worker 字段 | 同上（改 reader 参数或直接调策略） | 同上 |
   | 新增策略 / 新分位秩 / 新窗口参数 | 同上（加对应断言组） | 同上 |

   **测试用例最小清单（按改动类型挑）**：
   - `RollingPercentileReader` 或 as-of 窗口变更 → 覆盖 eviction / 历史截断不变性 / minKeep 边界
   - RSI 计算变更 → 覆盖纯上涨/纯下跌边界 / 预热点剔除 / as-of 截断口径（周期末值 = 整周期值、乱序输入不变）
   - 分位阈值变更 → 覆盖分位秩数学正确性（roundPercentile / 最近秩实现）
   - 收益率口径变更 → 覆盖 price vs cumulativeReturn 差异 / 年化公式 / 负收益 / 参数非法返回 null
   - 卖出条件变更 → 覆盖三重条件（RSI 超买 + 持有天数 + 收益率门槛）单独和组合
   - 分批卖出变更 → 覆盖第 1 批 = 信号当日 / 无后续数据 → executed=false / 非交易日顺延 / 严格递增
   - 配置默认值变更 → **不改业务代码、只改 reader 构造参数** 重新跑现有断言（确保对配置变更不敏感）
   - 日期输入 / 持有天数计算变更 → 覆盖 `YYYY-MM-DD` 与 `YYYYMMDD` 两种格式（`new Date('YYYYMMDD')` 为 `Invalid Date`，会导致 `holdingDays` 为 `NaN`、卖出永不触发）

   **跑通标准**：
   - `GetDiagnostics` 0 个 error（允许 hint）
   - 命令行输出 `汇总：通过 N / 失败 0` 连续跑 3 次全绿
   - 不引入对 `Math.random()` 的依赖（测试必须 deterministic）

3. **决策：更新 / 新建 / 跳过**

   | 情形 | 动作 |
   |------|------|
   | 已有技能覆盖该模块（文件清单、流程、口径、入口） | **更新**该技能，只改受影响段落 |
   | 无可覆盖技能，且改动属于可复用的流程、约定或跨文件口径 | **新建**技能 |
   | 纯一次性调试、仅改文案错别字、格式调整且无复用价值 | 跳过技能更新，但仍需检查使用手册与用户可见文案是否受影响 |

4. **更新已有技能**
   - 同步：文件路径、入口函数、常量名与默认值、数据结构字段、流程步骤、限制条件、UI 行为。
   - **同步用户可见文案**：改动涉及的规则说明、口径提示、按钮/确认框、空状态与错误提示、表格列名、导出列名与汇总行、tooltip 标签都要逐项核对并更新；阈值/窗口/天数等数字继续引用 `appConfig`，不要写死。
   - 口径变化必须写明「旧口径 → 新口径」及影响面（哪些页面/导出/接口/文案随之变化）。
   - 破坏性变更（报告列变化、历史结果不可比、缓存键变化）必须在技能中显式标注。
   - 只改相关段落，不重写全文；不复制大段源码，引用路径与符号即可。
   - **如涉及策略/计算口径变更，必须在技能的「验证方法」段落更新对应的测试命令与通过标准**。

4.5. **同步使用手册**
   - 打开 `Front-End/src/config/userManualConfig.ts`，按第 1 步列出的 `menuKey` 更新 `features`。
   - 新增页面必须新增条目；页面结构/交互/口径/文案变化必须修改条目；纯内部重构且用户完全无感知时，在最终回复注明「本次无需更新使用手册」。
   - 使用手册文案必须与页面当前实际行为逐条核对，不能保留已删除的功能描述。
   - `menuKey` 与 `menuConfig.tsx` 不一致时，使用手册页面无法匹配路径，视为无效条目。

5. **新建技能**
   - 目录名与 frontmatter `name` 保持一致，kebab-case。
   - `description` 单行，包含「做什么 + 何时调用 + 不适用场景」，带足触发词。
   - 正文写：触发条件、涉及文件、步骤、口径与常量、验证方法（含对应测试命令）、已知限制；控制在 500 行内，长内容放 `references/`。
   - 不创建 `README.md`、`CHANGELOG.md` 等人类文档。

6. **校验**
   - `name` 合法且等于目录名；frontmatter 可解析；`description` 单行、无 `: `、无尖括号。
   - 正文引用的文件/符号真实存在；常量默认值与代码一致。
   - 技能描述的行为与当前代码逐条对得上，不写「计划中」「可能」等未落地内容。
   - **文案校验**：改动涉及的所有用户可见文案已同步（规则说明、口径提示、按钮/确认框、空状态/错误提示、列名、导出汇总、tooltip），且数字类文案仍由 `appConfig` 插值、与当前配置一致。
   - **使用手册校验**：涉及页面改动的 `menuKey` 已在 `userManualConfig.ts` 中新增或更新，描述与页面当前行为一致、无过期条目；`menuKey` 与 `menuConfig.tsx` 的叶子菜单 key 一一对应。
   - `AGENTS.md` 的技能索引表条目与实际 `.trae/skills/<folder>/SKILL.md` 一一对应、链接可打开；`.claude/skills` 软链仍指向 `.trae/skills`。`AGENTS.md` 的常用命令、开发约定如受影响也已同步。
   - 各 IDE 指针文件保持「薄」：只引用 `AGENTS.md`，不出现与 `AGENTS.md` 冲突或重复的规则。
   - **如改动涉及公共方法/计算内核**：测试文件已更新 → 跑通 → 命令行输出 `N/失败 0`。

7. **回复中报告**
   - 列出本次「更新了哪个技能 / 新建了哪个技能 / 为什么跳过」，各一句话说明改动点。
   - **列出本次同步的用户可见文案**（文件 + 位置 + 改了什么）；无文案变化时注明「本次无文案变化」。
   - **列出本次同步的使用手册条目**（`menuKey` + 新增/修改/删除）；无需更新时注明「本次无需更新使用手册」。
   - **如跑了测试**：列出测试文件路径、总断言数、通过/失败数、连跑次数。
   - 如改动了技能索引或文档索引，说明 `AGENTS.md` 已同步；指针文件若无需变更则注明「无需改动」。

## 禁止

- 代码已改但技能保持旧口径、旧路径、旧默认值。
- **页面代码已改但使用手册 `userManualConfig.ts` 未同步**（新增页面缺条目、已有页面保留过期描述）。
- **代码已改但用户可见文案未同步**（规则说明、口径提示、按钮/确认框、空状态/错误提示、列名、导出汇总、tooltip 任一遗漏）。
- **在文案中写死阈值/窗口/天数等数字**（必须从 `appConfig` 插值，避免改配置后文案与实际口径不一致）。
- 为一次性问题新建技能，或为同一主题重复建多个技能。
- 修改与本次改动无关的技能内容。
- 在技能里写未经验证的行为、虚构的接口或常量。
- **改了公共方法 / 策略计算内核 / RSI/分位/收益率口径却跳过测试用例补充**。
- **测试用例依赖 `Math.random()` 导致偶发失败**（必须 deterministic）。
- **替用户执行 `git add` / `git add .` / `git add -A` 或主动暂存文件**（除非用户明确要求）。
